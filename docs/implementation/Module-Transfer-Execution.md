# モジュール転送型実行仕様 (Ansible 互換モデル)

本ドキュメントでは、本家 Ansible と同様に、モジュールファイルをターゲットノードに転送し、ターゲット上の Python インタプリタで実行する方式（モジュール転送型）の仕様について記述します。

## 1. 概要

モジュール転送型実行は、ターゲットノード上で直接モジュールを動作させる方式です。制御ノード側の GraalPy に依存せず、ターゲット環境の Python インタプリタとライブラリを利用します。

## 2. 実行フロー

実行は以下のステップで行われます。

1. **モジュールのパッケージング**:
    - 実行対象のモジュール（Python スクリプト）と、依存する `module_utils` を一つの実行可能ユニットにまとめます。
    - Ansible 本家における Ansiballz 形式（ZIP 圧縮されたスクリプト）と同様のパッケージングを行います。
2. **一時ディレクトリの作成**:
    - ターゲットノード上に実行用のテンポラリディレクトリ（例: `~/.ansible/tmp/`）を作成します。
3. **ファイルの転送**:
    - `Connection.putFile()` メソッドを使用して、パッケージングされたモジュールをターゲットの一時ディレクトリに転送します。
4. **リモート実行**:
    - ターゲットノード上の Python インタプリタを呼び出し、転送したモジュールを実行します。
    - 例: `/usr/bin/python3 /tmp/ansible_module_XXXX.py`
5. **結果の回収**:
    - モジュールが標準出力に書き出した JSON 形式の実行結果をキャプチャします。
6. **クリーンアップ**:
    - 実行完了後、ターゲットノード上の一時ディレクトリとファイルを削除します。

## 3. 必要な要件

- **ターゲットノード**:
    - モジュールの実行に必要なバージョンの Python インタプリタがインストールされていること。
    - モジュールが依存する OS パッケージやライブラリが存在すること。
- **制御ノード**:
    - `Connection` プラグインが `putFile`（SCP/SFTP 等）をサポートしていること。

## 4. GraalPy 委譲モデルとの比較

| 項目 | GraalPy 委譲モデル (現状) | モジュール転送型 (本モデル) |
| :--- | :--- | :--- |
| **Python 実行場所** | 制御ノード (GraalPy) | ターゲットノード (System Python) |
| **ターゲットの Python** | 不要 | 必要 |
| **転送オーバーヘッド** | なし (コマンドのみ) | あり (スクリプト一式) |
| **互換性** | GraalPy の制約を受ける | ターゲットの Python 環境に依存 |
| **主な用途** | 高速な実行、Python 不在環境 | 複雑な依存関係を持つモジュール |

## 5. 実装方針

`graal-ansible` において本モデルを実装する場合、`ITaskExecutor` または `Module` インターフェースの拡張により、接続先（Connection）のプロパティに応じて実行方式を選択可能にします。
