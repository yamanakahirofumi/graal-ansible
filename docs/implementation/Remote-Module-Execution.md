# リモートノードでのモジュール実行仕様 (Ansiballz)

本ドキュメントでは、`graal-ansible` がターゲットノード（ターゲットマシン）に対して Ansible モジュールを実行する際の仕組みについて詳述します。本プロジェクトでは、本家 Ansible と同様に、モジュールファイルをターゲットノードに転送し、ターゲット上の Python インタプリタで実行する「モジュール転送型（Ansiballz）」のモデルを採用しています。

## 1. 実行モデル：モジュール転送型実行 (Ansiballz)

モジュール転送型実行は、ターゲットノード上で直接モジュールを動作させる方式です。管理ノード側の GraalPy に依存せず、ターゲット環境の Python インタプリタとライブラリを利用します。

### 仕組み
1. **モジュールのパッケージングと依存関係の解消 (Ansiballz)**:
    - **ラッパースクリプトの生成**: 実行対象のモジュール（Python スクリプト）と引数、および実行環境をセットアップするためのラッパースクリプトを生成します。
    - **依存ファイルの集約 (Ansible Core)**: モジュールの実行に不可欠な `ansible.module_utils` および関連するコアファイル (`ansible/__init__.py`, `ansible/release.py`) を ZIP 形式にまとめ、モジュール本体と合体させた Ansiballz パッケージを作成します。
    - 本プロジェクトでは、実行効率化のため共通の依存関係 ZIP (`ansible_lib.zip`) を別途転送するハイブリッド方式をベースとしています。
2. **一時ディレクトリの作成**:
    - ターゲットノード上に実行用のテンポラリディレクトリ（例: `~/.ansible/tmp/`）を作成します。
3. **ファイルの転送**:
    - Java 側の `Connection.putFile()` メソッド（SSH の場合は SCP/SFTP）を使用して、以下のファイルをターゲットの一時ディレクトリに転送します。
        - 生成されたラッパースクリプト (例: `file.py`)
        - 依存関係 ZIP ファイル (例: `ansible_lib.zip`)
4. **リモート実行**:
    - ターゲットノード上の Python インタプリタを呼び出し、転送したラッパースクリプトを実行します。
    - `Connection.execCommand()` を通じて、リモートコマンド（例: `python3 /tmp/ansible.UUID/file.py`）を発行します。
    - ラッパースクリプト内では、転送された ZIP ファイルを `sys.path` に追加し、`ansible.module_utils` 等がインポート可能な状態でモジュール本体を実行します。
5. **結果の回収**:
    - モジュールが標準出力に書き出した JSON 形式の実行結果をキャプチャし、Java 側の `TaskResult` に変換します。
6. **クリーンアップ**:
    - 実行完了後、ターゲットノード上の一時ディレクトリとファイルを削除します。

## 2. SSH 接続の実装 (`SshConnection`)

SSH 経由のリモート実行およびファイル転送は `SshConnection.java` で実装されています。

- **ライブラリ**: Apache MINA SSHD を使用。
- **認証**: パスワード認証および公開鍵認証をサポート。
- **コマンド実行**: `ChannelExec` を使用してリモートコマンドを実行。
- **ファイル転送**: `ScpClient` を使用して、パッケージングされたモジュールのアップロード（`putFile`）を実現。

## 3. 利点と要件

### 利点
- **完全な互換性**: ターゲットノードの Python 環境で実行されるため、ネイティブな `os` 操作や複雑な依存関係を持つモジュールが本家 Ansible と同様に動作します。
- **隔離性**: 各タスクがターゲット上の独立したプロセスとして実行されます。

### 要件
- **ターゲットノード**: Python インタプリタがインストールされている必要があります。
- **制御ノード**: ターゲットへのファイル転送権限が必要です。
