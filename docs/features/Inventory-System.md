# インベントリシステム (Inventory System)

`graal-ansible` がサポートするターゲットノード管理（インベントリ）の機能仕様および動作ルールを定義します。

## 1. サポート形式とプロバイダー自動検出

`graal-ansible` は、静的ファイル、動的スクリプト、Python インベントリプラグイン、およびインベントリディレクトリを統合的に扱うインベントリ機構（`InventoryManager`）を備えています。

### 1.1 静的ファイル (File Inventory)
- **INI 形式**: セクション、変数、子グループ定義をサポート。
- **YAML 形式**: 階層構造、変数定義をサポート。
- **自動検出判定 (`FileInventoryProvider`)**:
  - ファイルが存在し通常ファイルであること。
  - **Linux / macOS**: 実行可能属性が付与されていないファイル（`!file.canExecute()`）を静的ファイルとして処理。
  - **Windows**: Windows 環境では実行可能属性の判定が不正確になる場合があるため、拡張子（`.ini`, `.yml`, `.yaml`, `.txt`）に基づいて静的ファイルとして判定。

### 1.2 外部スクリプト (Dynamic Inventory Scripts)
- **スクリプト方式 (`ScriptInventoryProvider`)**: 実行可能プログラムから `--list` 引数付きで起動し、標準出力から得られる JSON データを解析してインベントリに統合。
- **自動検出判定**:
  - **Linux / macOS**: 実行可能属性が付与されているファイル（`file.canExecute()`）。
  - **Windows**: スクリプト拡張子（`.py`, `.bat`, `.ps1`, `.exe`）を持つファイル。Windows 環境で `.py` ファイルを実行する際は、自動的に `python <script> --list` コマンドとして起動。

### 1.3 Python ベースのインベントリ・プラグイン (Inventory Plugins)
- **プラグイン方式 (`PythonInventoryProvider`)**: GraalPy 上でオリジナルの Ansible Python インベントリプラグインを直接実行（Python-first アプローチ）。
- **自動検出判定**:
  - 拡張子が `.yml` または `.yaml` のファイル。
  - YAML の最上位ルートに `plugin` キー（例: `plugin: test_ns.test_coll.test_plugin`）が定義されている場合、静的 YAML ファイルではなく Python インベントリプラグイン用設定ファイルとして判定。

### 1.4 動的更新 (Runtime Update)
- **add_host モジュール**: Playbook の実行途中で新しいホストをインベントリへ動的に追加し、グループや変数を割り当てる機能をサポート。
- **group_by モジュール**: モジュール実行で収集されたファクト値に基づいて、実行時にグループを動的に作成・分類する機能をサポート。

### 1.5 プロバイダー自動判別の優先順位

`InventoryManager` は、渡されたインベントリソースに対して以下の順序で登録プロバイダーの `supports(source)` を評価し、最初に適合したプロバイダーで読み込みを行います：

1. **`ScriptInventoryProvider`**: 実行可能ファイルまたはスクリプト。
2. **`PythonInventoryProvider`**: トップレベルに `plugin` キーを持つ YAML ファイル。
3. **`FileInventoryProvider`**: 通常の静的 INI / YAML ファイル。

未対応の形式が直接指定された場合は例外（`RuntimeException`）が発生しますが、ディレクトリ走査中に発見された未知のファイルは警告ログを出力してスキップされます。

## 2. インベントリディレクトリ走査と除外規則

単一のファイルパスだけでなく、ディレクトリを `-i` / `--inventory` 引数に指定することが可能です。

### 2.1 ディレクトリの再帰走査とソート順
- ディレクトリが指定された場合、配下のファイルを再帰的に探索します。
- 探索されたファイル群は、**ファイル名（ベース名）の大文字・小文字を区別しないアルファベット昇順（Case-Insensitive Alphabetical Order）** でソートされた上で順次読み込まれ、同一の `Inventory` オブジェクトへマージされます。

### 2.2 除外ルール (Ignored Files & Directories)
ディレクトリ走査時、以下のファイルおよびディレクトリはインベントリソースとして読み込まれず、自動的にスキップされます：

- **隠しファイル**: `.` で始まるファイル（例: `.git`, `.gitignore`）。
- **一時・バックアップファイル**: `~`, `.bak`, `.old`, `.orig`, `.retry`, `.rpmnew`, `.rpmsave`, `.tmp` で終わるファイル。
- **変数ディレクトリ**: `vars`, `group_vars`, `host_vars` という名称のディレクトリ（これらは後述の変数スコープとして別途自動ロードされます）。

## 3. インベントリ変数とディレクトリ変数スコープ (`group_vars` / `host_vars`)

インベントリに関連する変数定義は、Ansible 互換の変数優先順位（Level 3, 4, 6, 8, 9）に従って厳密に解決されます。

### 3.1 変数優先順位の定義

| 優先度 | 変数のソース | 説明 |
| :---: | :--- | :--- |
| Level 3 | インベントリファイル / スクリプトのグループ変数 | INI の `[group:vars]`、YAML の `group.vars`、スクリプトの `group.vars`。 |
| Level 4 | インベントリ `group_vars/all` | インベントリディレクトリ配下の `group_vars/all` (ファイルまたはディレクトリ)。 |
| Level 6 | インベントリ `group_vars/<group_name>` | インベントリディレクトリ配下の `group_vars/<group_name>`。グループ階層順にマージ。 |
| Level 8 | インベントリファイル / スクリプトのホスト変数 | INI のホスト行インライン変数、YAML の `hosts.<host>.vars`、スクリプトの `_meta.hostvars`。 |
| Level 9 | インベントリ `host_vars/<host_name>` | インベントリディレクトリ配下の `host_vars/<host_name>` (ファイルまたはディレクトリ)。 |

### 3.2 複数グループに属する場合のマージ挙動
ターゲットホストが複数のグループに属している場合、インベントリツリーの親子関係（`all` -> 親グループ -> 子グループ）に沿ってグループ変数が継承・上書きマージされます。
ホスト固有の変数（Level 8, Level 9）は、すべてのグループ変数（Level 3〜Level 7）よりも高い優先度を持ち、常にグループ変数を上書きします。

## 4. ホスト（ターゲットノード）パターンのマッチングと範囲パターン展開

Playbook の `hosts` ディレクティブや CLI の `--limit` オプションで使用されるホストパターンの構文解析ルールです。

### 4.1 基本パターンと論理結合
- **基本マッチング**: 単純なホスト名、グループ名、およびすべてのホストを表す `all` をサポート。
- **複数パターン指定**: カンマ（`,`）またはコロン（`:`）区切りでの複数パターン指定に対応。
- **ワイルドカード**: `*` による部分一致（例: `web*`, `*.example.com`）に対応。

### 4.2 範囲パターン展開 (Range Pattern Expansion)
`[start:end]` または `[start-end]` 構文によるホスト番号・記号の範囲指定に対応します。

- **範囲区切り文字**: `:` および `-` の双方が使用可能（例: `web[1:5]` および `web[1-5]`）。
- **数値範囲**: `web[1:3]` -> `web1, web2, web3`
- **ゼロ埋め（ゼロパディング）**: `node[01:03]` -> `node01, node02, node03`（開始値の桁数に合わせて自動パディング）。
- **アルファベット範囲**: `db[a:c]` -> `dba, dbb, dbc`
- **逆順（リバース）範囲**: `node[3:1]` -> `node3, node2, node1`
- **直積展開 (Cartesian Product)**: 単一パターン内の複数ブラケット（例: `app[1:2]-dc[a:b]` -> `app1-dca, app1-dcb, app2-dca, app2-dcb`）に対応。

### 4.3 ブラケットを考慮した分割 (Bracket-Aware Splitting)
パターンリストをカンマやコロンで分割する際、範囲指定ブラケット `[...]` の内部に含まれるコロンやカンマ（例: `web[0:5],db_servers`）は分割デリミタとして扱われず、安全に保護されます。

## 5. インベントリの自動検出とデフォルト挙動

- **明示的な指定**: 環境依存を避けるため、`-i` / `--inventory` オプションによる明示的なファイルまたはディレクトリの指定を推奨します。
- **未指定時の挙動**: CLI 実行時に `-i` が省略された場合、ホストが未定義の空インベントリとして処理され、警告ログが出力されます。
