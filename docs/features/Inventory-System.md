# インベントリシステム (Inventory System)

`graal-ansible` がサポートするターゲットノード管理（インベントリ）の機能仕様を定義します。

## 1. サポート形式とプロバイダー自動検出

### 1.1 静的インベントリファイル (`FileInventoryProvider`)
- **INI 形式**: セクション (`[group]`)、ホスト変数 (`key=value`)、グループ変数 (`[group:vars]`)、子グループ構造 (`[group:children]`) をサポート。
- **YAML 形式**: 階層構造（`all.children.group.hosts`）、ホスト変数、グループ変数をサポート。
- **OS 依存の判定条件**:
  - **POSIX (Linux/macOS)**: ファイルが存在し、実行権限（`file.canExecute()`）を持たないファイルを静的インベントリファイルとして自動判定。
  - **Windows**: 実行権限の扱いが異なるため、ファイル拡張子（`.ini`, `.yml`, `.yaml`, `.txt`）に基づいて静的ファイルとして判定。

### 1.2 動的インベントリスクリプト (`ScriptInventoryProvider`)
- **JSON インターフェース**: `--list` コマンドライン引数を付与して外部プログラムを実行し、標準出力に返却された JSON を解析。
- **データ構造仕様**:
  - `_meta.hostvars`: ホストごとの変数を集約して格納。
  - グループオブジェクト: `hosts` (リスト), `vars` (マップ), `children` (リスト) を保持。
- **OS 依存の判定条件**:
  - **POSIX (Linux/macOS)**: 実行権限（`file.canExecute()`）を持つファイルを動的スクリプトとして判定。
  - **Windows**: `.py`, `.bat`, `.ps1`, `.exe` 拡張子を持つファイルをスクリプトとして判定（`.py` の場合は自動的に `python` インタープリタを前置して実行）。

### 1.3 インベントリ・プラグイン (`PythonInventoryProvider`)
- **Python-first アプローチ**: GraalPy 上で Ansiballz / Ansible コア互換の Python 製 Inventory Plugin を動的にロード・実行。
- **自動判定条件**: `.yml` または `.yaml` 設定ファイルの最上位に `plugin` キー（例: `plugin: amazon.aws.aws_ec2`）が定義されている場合、自動的にインベントリ・プラグインとして認識。

### 1.4 動的更新 (Runtime Update)
- **add_host モジュール**: 実行時に新しいホストをインベントリに追加し、グループに割り当てる機能をサポート。
- **group_by モジュール**: ファクトに基づいて実行時にグループを動的に作成・分類する機能をサポート。

## 2. ディレクトリ・インベントリと除外ルール

### 2.1 ディレクトリ走査と処理順序
- `-i` オプションにディレクトリが指定された場合、配下のインベントリソースを再帰的に走査。
- 発見されたファイルは、ベース名の大文字・小文字を区別しないアルファベット順（`f.getName().toLowerCase()`）にソートして一貫した順序で解析・マージ。

### 2.2 自動除外対象 (Exclusion Rules)
以下のファイルおよびディレクトリは、インベントリファイルの走査対象から自動的に除外されます。
- **隠しファイル**: `.` で始まるファイル（例: `.git`, `.DS_Store`）。
- **バックアップ・一時ファイル**: `~`, `.bak`, `.old`, `.orig`, `.retry`, `.rpmnew`, `.rpmsave`, `.tmp` で終わるファイル。
- **予約ディレクトリ**: `vars`, `group_vars`, `host_vars`（変数ディレクトリとして別途処理されるため）。

### 2.3 エラー処理仕様
- **単一ファイルの明示指定**: ユーザーが `-i` で指定したファイルがどのプロバイダーでもサポートされない（または存在しない）場合、`RuntimeException` を発生させて実行を停止。
- **ディレクトリ走査時**: 走査中にサポート対象外のファイル（未対応の拡張子やバイナリ等）を発見した場合は、警告ログ（`LOGGER.warning`）を出力してスキップし、他のファイルの処理を継続。

## 3. group_vars および host_vars ディレクトリ仕様

### 3.1 ディレクトリ階層と変数適用範囲
インベントリファイル単体とは別に、インベントリディレクトリおよびプレイブックディレクトリ直下の `group_vars/` および `host_vars/` ディレクトリから自動的に変数を読み込みます。

- **`group_vars/all`**: 全ホストに適用される共通変数。
- **`group_vars/<group_name>`**: 特定のグループに所属するホストに適用される変数。
- **`host_vars/<host_name>`**: 特定のホストに適用されるホスト固有変数。

### 3.2 ディレクトリ構成とファイル拡張子
`group_vars` / `host_vars` 内のターゲット（グループ名またはホスト名）は、以下のいずれかの形式で配置可能です。
1. **単一ファイル形式**: `<name>.yml`, `<name>.yaml`, `<name>.json`
2. **サブディレクトリ形式**: `<name>/` ディレクトリを作成し、その直下に複数ファイル（`.yml`, `.yaml`, `.json`）を配置。アルファベット順にソートされて順次マージされます。

### 3.3 優先順位とのマッピング
[変数とテンプレートの実装詳細](../implementation/Variables-Templating.md#2-変数優先順位-variable-precedence) で定義される22段階の変数優先順位のうち、以下のレベルを担います。
- **Level 4**: Inventory `group_vars/all`
- **Level 5**: Playbook `group_vars/all`
- **Level 6**: Inventory `group_vars/*`
- **Level 7**: Playbook `group_vars/*`
- **Level 9**: Inventory `host_vars/*`
- **Level 10**: Playbook `host_vars/*`

## 4. ホストパターンのマッチングと範囲展開仕様

### 4.1 基本マッチングと複数指定
- **単一指定**: ホスト名、グループ名、またはルートグループ `all` を指定。
- **複数指定区切り**: カンマ（`,`）またはコロン（`:`）で区切られた複数パターンの指定をサポート。
- **ワイルドカード**: `*` を使用したワイルドカードマッチ（例: `web*`, `*.example.com`）。

### 4.2 ブラケットを考慮した分割 (Bracket-Aware Splitting)
パターンをカンマやコロンで分割する際、範囲指定ブラケット `[...]` の内部に含まれるコロンやカンマ（例: `web[0:5],db`）は区切り文字として扱わず、ブラケットのネスト深度が 0 の位置のみで分割。

### 4.3 範囲パターン展開 (Range Pattern Expansion)
- **数値範囲**: `[start:end]` および `[start-end]`（例: `web[1:5]` -> `web1, web2, web3, web4, web5`）。
- **ゼロ埋め（Zero-Padding）**: 開始文字列がゼロで埋められている場合（例: `[01:05]`）、桁数を維持して `01, 02, 03, 04, 05` に展開。
- **アルファベット範囲**: `[a:e]` および `[a-e]`（例: `db[a:c]` -> `dba, dbb, dbc`）。
- **逆順（リバース）展開**: `[5:1]` や `[c:a]` などの減少・逆順パターンに対応。
- **直積展開（Cartesian Product）**: 1つのパターン内に複数のブラケットが存在する場合（例: `node[1:2]-site[a:b]`）、直積 `node1-sitea, node1-siteb, node2-sitea, node2-siteb` へと再帰的に展開。
- **リテラルフォールバック**: ブラケット内部が数値/アルファベット範囲にマッチしない場合や閉じていない場合は、リテラル文字列として維持。
