# インベントリシステム (Inventory System)

`graal-ansible` がサポートするターゲットノード管理（インベントリ）の機能仕様、サポート形式、外部連携、変数解決規則、およびホストパターン解析仕様を定義します。

## 1. サポート形式と構造仕様

`graal-ansible` は静的インベントリ定義ファイル（INI, YAML）、実行時動的更新、および外部インベントリ連携（スクリプト、プラグイン）を包括的にサポートします。

### 1.1 静的ファイル (Static Inventory Files)

#### INI 形式
INI 形式のインベントリファイルは、セクションヘッダーを用いてグループ、子グループ、およびグループ変数を構造化します。

- **デフォルト所属 (`all` グループ)**: ファイル先頭のセクションヘッダー以前に記述されたホストは、暗黙的に最上位グループ `all` に属します。
- **ホスト個別変数**: ホスト名の後にスペース区切りで `key=value` 形式の変数を付与可能です（例: `web1 ansible_host=192.168.1.10 ansible_port=22`）。
- **グループセクション (`[group_name]`)**: 当該ヘッダー配下に列挙されたホストを、指定グループのメンバーとして登録します。
- **子グループセクション (`[group_name:children]`)**: `group_name` の子グループとしてネストするグループ名を列挙します。
- **グループ変数セクション (`[group_name:vars]`)**: 当該グループ配下の全ホストに適用されるグループ変数を `key=value` 形式で定義します。
- **範囲ホスト指定**: INI ファイル内のホスト行において `node[01:10].example.com` などの範囲指定が記述されている場合、パーサーにより個別のホスト定義へと展開されます。

#### YAML 形式
YAML 形式のインベントリファイルは、インデントによるネスト構造を用いてグループ階層と変数を定義します。

- **ルート要素**: 原則として `all` グループをルートマップとして定義します。
- **ホスト定義 (`hosts`)**: 各グループの `hosts` キー配下にホスト名をキーとするマップを定義し、値としてホスト個別の変数をマップ形式で指定します。
- **子グループ定義 (`children`)**: 各グループ配下の `children` キーに、子グループの辞書構造を再帰的にネスト定義します。
- **グループ変数 (`vars`)**: 各グループ配下の `vars` キーに、グループ変数をマップ形式で定義します。

### 1.2 動的更新 (Runtime Dynamic Update)

Playbook の実行中に、タスクの実行結果やファクト収集データに基づいてインベントリを動的に操作・更新する機能をサポートします。

- **`ansible.builtin.add_host` モジュール**:
  - 実行時に新しいターゲットノード（ホスト）をインベントリへ追加します。
  - `name` (または `hostname`) パラメータで指定されたホストを作成し、`groups` パラメータで指定されたグループ（カンマ区切りまたはリスト）へ所属させます。
  - 任意の追加パラメータは、当該ホストの固有変数（ホスト変数）として動的にバインドされます。
- **`ansible.builtin.group_by` モジュール**:
  - 収集されたファクトや変数の値に基づき、ホストを動的に分類する新しいグループを作成します。
  - `key` パラメータで指定された文字列（Jinja2 テンプレート評価値）をグループ名として生成し、現在実行中のホストをそのグループに追加します。
  - グループ名に含まれる不正な文字（スペースやハイフン等）はアンダースコア（`_`）へ自動サニタイズされます。

### 1.3 外部インベントリ (Dynamic Inventory Integration)

クラウド環境や CMDB、外部データソースから動的にホスト情報を取得する外部連携方式をサポートします。

#### インベントリ・スクリプト方式 (`ScriptInventoryProvider`)
任意の実行可能スクリプト（Python, Bash, バイナリ等）を実行し、JSON 出力をインベントリへ統合します。

- **実行プロトコル**:
  - 対象ファイルに実行権限（Executable）が付与されている場合、管理ノードのローカルプロセスとして `--list` 引数を渡して起動します。
- **JSON データスキーマ仕様**:
  - トップレベルの各キーはグループ名を表し、`hosts`（所属ホストリスト）、`vars`（グループ変数マップ）、`children`（子グループ名リスト）を含みます。
  - `_meta.hostvars` オブジェクトが存在する場合、各ホストに対応するホスト変数マップとして内部インベントリへ透過的に展開・登録されます。
- **環境変数の継承**:
  - 管理ノードの実行時環境変数を安全にプロセスへ継承し、必要に応じて Ansible 互換の環境変数を動的伝播します。

#### インベントリ・プラグイン方式 (`PythonInventoryProvider` - Python-first)
GraalPy を介して Ansible 本家の Python 製インベントリプラグインを直接ロード・実行します。

- **自動検出条件**:
  - ファイル拡張子が `.yml` または `.yaml` であること。
  - YAML のトップレベルマップに `plugin` キー（例: `plugin: host_list`, `plugin: test_ns.test_coll.custom_plugin`）が定義されていること。
- **GraalPy 連携メカニズム**:
  - `ansible_inventory_launcher.py` を経由してオリジナルの Python プラグインインスタンス（`BaseInventoryPlugin` 派生クラス）を生成し、`parse(inventory, loader, path)` を呼び出します。
  - プラグインが構築した `InventoryData` を JSON にシリアライズして Java 側で受領し、Java の `Inventory` レコードへマージします。

## 2. インベントリ・ディレクトリの走査と除外規則

単一ファイルだけでなく、ディレクトリをインベントリソース（`-i <directory>`）として指定した場合の動作仕様です。

### 2.1 ディレクトリ走査と処理順序
- **再帰走査**: 指定されたディレクトリ配下の全サブディレクトリを再帰的に走査してインベントリファイルを収集します。
- **アルファベット順ソート**: 収集されたファイルは、ディレクトリパスではなく**ファイル単体のベース名（小文字正規化）**を基準としてアルファベット昇順（Case-Insensitive Lexicographical Order）にソートされ、決定論的な順序で読み込み・マージされます。

### 2.2 除外ルール (Ignored Files & Directories)
走査処理において、以下の命名パターンに一致するファイルおよびディレクトリは探索から自動的に除外（無視）されます。

| 分類 | 除外パターン・名称 | 理由・背景 |
| :--- | :--- | :--- |
| **隠しファイル** | `.` で始まるファイル・ディレクトリ | エディタ設定、VCS 差分、OS 一時ファイルの誤読み込み防止 |
| **バックアップファイル** | `~`, `.bak`, `.old`, `.orig`, `.retry`, `.tmp` で終わるファイル | バックアップ・一時ファイルの重複読み込み防止 |
| **パッケージ管理一時ファイル** | `.rpmnew`, `.rpmsave` で終わるファイル | OS パッケージ更新時の差分ファイルの除外 |
| **予約変数ディレクトリ** | `vars`, `group_vars`, `host_vars` という名称のディレクトリ | インベントリ定義ではなく変数解決レイヤーで別途読み込まれるため |

### 2.3 エラーハンドリングの差異
- **CLI / API 明示指定時**: ユーザーが単一ファイルとして明示的に指定したパスが、いずれの `InventoryProvider` にもサポートされていない場合、即座に例外（`RuntimeException` / `AnsibleException`）を送出して実行を停止します。
- **ディレクトリ走査時**: ディレクトリ配下で未知の拡張子やバイナリファイル、非サポートファイルが発見された場合は、警告ログ（`LOGGER.warning`）を出力した上で安全にスキップし、他の正常なインベントリファイルの処理を継続します。

## 3. 変数スコープと優先順位 (Variable Hierarchy & Precedence)

インベントリから供給される変数は、Ansible 本家互換の変数優先順位（[変数とテンプレートの実装詳細](../implementation/Variables-Templating.md#2-変数優先順位-variable-precedence)）に従って解決されます。

### 3.1 インベントリ内変数優先階層
インベントリ内部で定義された変数は、以下の昇順（下位が上位を上書き）でマージされます。

```
1. 最上位 'all' グループ変数 (Level 3)
   └── 2. 親グループ変数 (Level 3)
        └── 3. 子グループ変数 (Level 3)
             └── 4. ターゲットノード固有変数 / hostvars (Level 8)
```

### 3.2 複数グループ所属ホストにおけるマージ規則
- ターゲットノードが複数のグループに属している場合、ルートグループ `all` から当該ホストに至るすべてのグループパス（`paths`）が収集されます。
- 同一グループ階層内では各パス上のグループ変数が順次マージされ、子グループの変数が親グループの変数を上書きします。
- ターゲットノード固有の変数（`Host.variables`）は、すべてのグループ変数マージ結果に対して最終的に適用され、同一名の変数が存在する場合はホスト変数が最優先で採用されます。
- インベントリホスト変数（Level 8）は、Playbook レベルで定義されるグループ変数（Level 7）よりも高い優先順位を持ち、これを上書きします。

## 4. ホストパターンのマッチングと範囲パターン展開

Playbook の `hosts` ディレクティブや CLI オプション `--limit` (`-l`) におけるホスト選択パターンの評価仕様です。

### 4.1 Bracket-Aware Splitting（ブラケット保護分割）
複数パターンがカンマ（`,`）またはコロン（`:`）で指定された場合、範囲ブラケット `[...]` の内部に含まれる区切り文字を保護しつつ正確にトークン分割を行います。

- **アルゴリズム**: 文字列を先頭から走査し、ブラケット深度カウンタが `0` の位置にあるカンマまたはコロンでのみトークンを分割します。
- **例**: `web[0:5],db_servers:backup[1-2]` -> `["web[0:5]", "db_servers", "backup[1-2]"]` に分割。

### 4.2 範囲パターンの展開仕様 (Range Pattern Expansion)

ホスト名トークンに含まれるブラケット指定は、`HostPatternParser` により完全なホスト名リストへと動的に展開されます。

| 範囲形式 | 指定例 | 展開結果 | 補足仕様 |
| :--- | :--- | :--- | :--- |
| **数値範囲** | `web[1:4]` / `web[1-4]` | `web1, web2, web3, web4` | コロン（`:`）およびハイフン（`-`）の双方を区切り文字として許容 |
| **ゼロパディング数値** | `db[01:05]` | `db01, db02, db03, db04, db05` | 開始文字列の桁数に合わせたゼロ左詰め（Zero-Padding）を自動保持 |
| **アルファベット範囲** | `app[a:d]` / `app[A:D]` | `appa, appb, appc, appd` | ASCII 文字コード順に従う大文字・小文字の連続アルファベット展開 |
| **リバース（逆順）範囲** | `node[4:1]` / `srv[c:a]` | `node4, node3, node2, node1` | 開始値が終了値より大きい場合、ステップ `-1` で自動減少展開 |
| **複数ブラケット直積** | `srv[1:2]-dc[a:b]` | `srv1-dca, srv1-dcb, srv2-dca, srv2-dcb` | 単一パターン内に複数範囲が存在する場合、直積（Cartesian Product）を展開 |
| **非範囲フォールバック** | `host[invalid]` | `host[invalid]` | 正規表現にマッチしないブラケットはリテラル文字列として安全に維持 |

### 4.3 パターンマッチング規則
展開されたホストパターンは、以下の優先ルールでインベントリ内のホストと照合されます。

1. **`all` マッチ**: `all` または `*` が指定された場合、インベントリ内のすべてのホストを選択。
2. **完全一致**: ホスト名または定義済みグループ名と完全一致する対象を選択。
3. **ワイルドカード一致**: `web*` や `*.internal.net` などのグロブパターンによるホスト名・グループ名の一括選択。
