# インベントリシステム (Inventory System)

`graal-ansible` がサポートするターゲットノード管理（インベントリ）の仕様を定義します。

## 1. サポート形式

### 1.1 静的ファイル
- **INI 形式**: セクション、変数、子グループ定義をサポート。
- **YAML 形式**: 階層構造、変数定義をサポート。

### 1.2 動的更新 (Runtime Update)
- **add_host モジュール**: 実行時に新しいホストをインベントリに追加し、グループに割り当てる機能をサポート済み。
- **group_by モジュール**: ファクトに基づいて実行時にグループを動的に作成する機能をサポート済み。

### 1.3 外部インベントリ (Dynamic Inventory)
- **インベントリ・プラグイン (Python-first)**: GraalPy を活用し、Ansible 本来の Python 製インベントリプラグインをそのまま実行可能な仕組み（`PythonInventoryProvider`）を完全にサポートしています。
- **インベントリ・スクリプト**: JSON 形式を出力する外部のインベントリスクリプト（`ScriptInventoryProvider`）との連携をサポートしています。
- **詳細**: 詳細は [インベントリシステムの実装詳細](../implementation/Inventory-System.md#5-外部インベントリの統合-external-inventory-integration) を参照してください。

## 2. 実装上の留意点 (Implementation Considerations)

### 2.1 グループ変数の階層構造
- **仕様**: 親グループよりも子グループの変数を優先する標準的な挙動を実装。
- **状況**: 実装済み。詳細は [インベントリシステムの実装詳細](../implementation/Inventory-System.md) を参照。

### 2.2 ホスト（ターゲットノード）パターンのマッチングと範囲パターン展開

#### サポート範囲
- **基本マッチング**: 単純なホスト名、グループ名、`all` グループをサポート。
- **複数パターン指定**: カンマ（`,`）またはコロン（`:`）区切りでの複数パターン指定をサポート。
- **ワイルドカードマッチング**: `*` を用いたパターンマッチング（ホスト名およびグループ名双方に対応）をサポート。
- **範囲パターン展開 (Range Pattern Expansion)**: `[start:end]` または `[start-end]` 形式の範囲指定（例: `web[0:5]` や `web[0-5]`）に対応。
  - **範囲区切り文字**: `:` および `-` の双方が利用可能（例: `[1:5]` および `[1-5]`）。
  - **数値範囲**: `[1:5]` -> `1, 2, 3, 4, 5`
  - **ゼロ埋め（ゼロパディング）**: `[01:05]` -> `01, 02, 03, 04, 05`
  - **アルファベット範囲**: `[a:e]` -> `a, b, c, d, e`
  - **逆順（リバース）範囲**: `[5:1]` や `[e:a]` などの減少・逆順パターンに対応。
  - **複数範囲（直積）指定**: 単一パターン内の複数ブラケット展開（例: `web[1:2]-[a:b]` -> `web1-a, web1-b, web2-a, web2-b`）に対応。

#### 構文解析の特性（Bracket-Aware Splitting）
- 複数パターンをカンマ（`,`）やコロン（`:`）で分割する際、範囲指定ブラケット `[...]` の内部に含まれるコロンやカンマは無視され、パターン分割文字として扱われません。
  - 例: `web[0:5],db_servers` は、`web[0:5]` と `db_servers` の2つに正しく分割されます。

### 2.3 インベントリの自動検出
- **方針**: 環境依存を避けるため、`-i` オプションによる明示的な指定を推奨。
- **デフォルト探索**: カレントディレクトリの `hosts` ファイル等の最小限の探索に留める。

### 2.4 インベントリ・ディレクトリ走査と自動除外ルール
単一ファイルではなくディレクトリがインベントリソースとして指定された場合、`graal-ansible` はディレクトリ配下を再帰的に走査し、適合するインベントリファイルを探索します。

- **ファイル探索とソート**:
  - 発見されたファイルは、ベース名の大文字小文字を区別しないアルファベット順にソートされて読み込まれます。
- **自動除外ルール**:
  - 以下のファイルおよびディレクトリはインベントリ探索の対象から除外されます。

| 分類                           | 除外判定基準                         | 具体例・対象パターン                                                   |
| :----------------------------- | :----------------------------------- | :--------------------------------------------------------------------- |
| **隠しファイル**               | ファイル名が `.` で始まるファイル    | `.gitignore`, `.ansible.yml`                                           |
| **特定ディレクトリ**           | 変数定義用の予約済みディレクトリ名   | `vars`, `group_vars`, `host_vars`                                      |
| **一時・バックアップファイル** | 対象拡張子で終了するファイル名       | `~`, `.bak`, `.old`, `.orig`, `.retry`, `.rpmnew`, `.rpmsave`, `.tmp`  |

### 2.5 複数インベントリソースのマージ仕様
複数のインベントリソース（`-i inv1 -i inv2` やディレクトリ走査による複数ファイル）が指定された場合、以下のように透過的にマージされます：

- **グループ構造の統合**: 同名のグループは自動的に統合され、ホストおよび子グループ定義が集約されます。
- **変数の上書き**: 同一グループや同一ホストで変数が重複して定義されている場合、後から読み込まれたインベントリソースの値が既存の値を上書き（`replace`）します。
- **階層関係の保持**: 各ソースで定義されたグループ間の親子関係（`:children`）は、グローバルなインベントリツリー構造に安全に結合されます。
